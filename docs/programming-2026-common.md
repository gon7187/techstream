# CUW2026 common runtime

`scripts.programming_2026_common` supplies bounded host implementations of the recovered common value, diagnostic and preparation operations. It opens no transport. Matching native module identity establishes provenance; it does not certify that every export is implemented.

`ControlCommPhase2026.runtime_device()` returns only an actual J2534Device2026 bound to the runtime primitive, or the exact recorded driver/device retained by `NativeRuntime2026.bind_recorded_device2026(trace, device)`. The latter validates trace, transport, provider and device identities again on access and uses the actual device cleanup capability. Arbitrary trace snapshots are rejected. `ControlCommPhase2026.execute(engine, session)` applies the native engine→control ImportData/ExportData chronology only when an actual `J2534InterfacePair2026` is bound; unpaired callers must supply the already connected control view. `NativeRuntime2026(provider)` calls `provider(operation: dict, remaining_seconds: float)`. Operations describe a transport, timing, locking or specified cryptographic primitive. The provider cannot return a programming-stage success decision. Normal calls check cancellation and an overall monotonic deadline before and after the callback. Cleanup has an independent bounded timeout and call budget.

Use `acquire(operation, release_operation)` for a returned unsigned handle. It registers the handle before checking callback cancellation or lateness. Use `call_owned` for a void acquisition with a compensating stop/disconnect. `call_result_owned` registers a static compensation only for an exact integer native result (default DWORD1), before post-provider cancellation/deadline checks; Python `True` does not count as integer1. This is separate from J2534 status conventions. `release_with_result` returns the provider result, including a completed native false result, and consumes ownership before the elapsed-time check. A provider exception retains ownership and its original identity. `abandon_resource` only records a concrete caller's source-proven native abandonment: it makes no release or invalidation claim and performs no I/O. Host failures and cancellation still require compensation. `forget_invalidated_resource` retires one exact owned child entry without I/O only when a concrete caller has established that a successful parent disconnect already invalidated it. It is never a general ignore-cleanup-error operation. `owned_identifiers` provides a read-only tuple of exact handle-only entries, including an acquired handle whose cancellation rollback failed before the caller received it. It performs no I/O and proves no parent invalidation. Driver filters, driver periodic messages and logical-channel children in a pair retain an authenticated `J2534InterfacePair2026.channel_lease` at acquisition. A successful release of that exact channel generation or its exact parent device generation retires those children without another provider call or cleanup budget charge. Failed releases and reused raw IDs do not establish retirement. Sync-periodic stop entries retain local OS thread/mutex cleanup and are never retired just because a physical channel was released. The disconnect sweep only removes entries with a proven retired anchor; unanchored entries and other live generations remain owned. Failed releases otherwise remain owned for retry; `close()` attempts all remaining releases and returns their error types. Rollback failures preserve the original cancellation/deadline exception and add a note. Host policy bounds resources to 256. The ordinary call budget defaults to 65,536; `max_calls` explicitly allows up to 16,777,216 calls, with cleanup bounded independently. Large image callers must select a sufficient bounded budget from their actual transfer plan. Successful releases lose ownership before a post-callback deadline check; a late successful release is never repeated. `native_channel_connected2026()` observes the actual current native interface without I/O: `None` for an opaque low-level provider, `False` for a disconnected concrete view, and `True` only for a connected view whose paired physical generation remains valid. It does not create ownership or open a channel. A bound `J2534Device2026.primitive` automatically supplies its narrow `cleanup_primitive` capability; wrappers can pass `cleanup_action` explicitly.

`CanDiag2026` consumes complete immutable CAN Data bytes, including the request/response address. `write_messages` must return exactly one written message. `read_specified_can_message` returns a correctly addressed immutable frame. Ordinary, Phase5, Phase6 and UnifiedUtils profiles preserve their distinct busy/pending behavior, expected prefixes, minimum lengths, timeout restoration and transaction locks. `CommonResponseError.response` retains the private last payload; its printable message contains only the numeric error. Callers must redact this private payload and cryptographic action arguments from public reports.

`native_cancelled` binds the separate native callback-slot12 cancellation observation. `CanDiag2026.call(check_native_cancel=True)` validates that binding before I/O and queries it at each native receive-loop head. It raises the native empty `NativeException2026` on cancellation. Source helpers that set this flag, including software-ID, default/extended sessions, charge-local-bus and user-DTC reads, require the binding; host cancellation remains a separate policy.

`Unified2026` includes gateway classification, ignition-off cancellation, OTA stop, default/extended sessions, reset, DID/RoB reads, routine controls and central/Phase5/SMC security wire stages. The callback22/callback21 security-up composition has a concrete authorized AES128 ECB implementation. `NativeCentralGatewayKey2026.from_native_module` supplies slot20’s separate AES128 ECB producer from authenticated CUW mode1 metadata; bind it with `NativeRuntime2026.bind_central_gateway_key`. Its source key atRVA7ac40 is distinct from the mode0 engine gateway handshake input. `NativeSMCHmac2026.from_native_module` verifies the exact separately shipped CalculationHmacAPI image and privately obtains its fixed key. `NativeRuntime2026.bind_smc_hmac` binds the concrete HMAC-SHA256 port; repeated same-source bindings preserve the existing object. SMC follows load → resolve `MakeSendKeyCGWHmac` → invoke → free, including native missing-library/export errors and output failure. The input is the native leading `11` byte plus seed32; unbound opaque SMC crypto callbacks are rejected. The local static-port handles identify host library state, not actual Windows handles. Native source-string references in loader exceptions use `TCUWUnifiedUtils.dll:RVA8210` without publishing its private build path. `NativeRuntime2026.bind_p5_online(controller, chronology, advance_clock=...)` binds the concrete source-issued `OnlineKeyController2026` and `OnlineReplay2026` to the same engine worker/runtime. Callback26 uses seed16/output256, including the exact Ethernet ESW1 `calculate_esw1_key` path; callback27 uses seed8/output64 with the actual region2 controller. All three named operations reject opaque provider success. Suzuki gateway authorization routes to callback26 only for the exact `suzuki_uds`/`gateway` source branch; unrelated authorization slots remain distinct. The captured `SetReprogrammingKey` input drives native validation and result mutation. Captured elapsed time advances the shared replay clock exactly once, including failed input and cleanup; the binding requires an explicit clock-advance primitive. Other protocol-specific external security operations still require their exact source-bound producers. Block-size security helpers restore block size before releasing their own filter, attempt both cleanups and preserve resources owned by the caller.

`SecretInfoClient.from_native_module()` accepts only an authenticated reconstructed 2026 module and preserves the native client authorization boundary. `from_native_modules(secret_info_bytes, cuw_bytes)` verifies both exact module identities and derives the authorization client from the actual native CUW caller. An unauthorized client receives the native empty result. Its representation hides authorization bytes and records. `NativeSecurityComposer2026.from_native_modules()` binds the exact client, decrypts the sixteen-byte service-authentication block under native record0, then encrypts the seed under the derived key. `NativeRuntime2026.bind_security_composer()` computes only these two internal AES operations locally with the same deadline/cancellation/call budget; transport ownership and its provider remain unchanged. Linux system libcrypto supplies AES128 ECB without padding. Native records, intermediate keys and authorization text stay private. Factory issuance is checked and the client fields are immutable; a manually constructed client cannot enter native security operations.

`NativeBytes2026.convert_bytes_to_string` preserves the separate static four-argument export: it writes uppercase pairs and NUL only when the whole selected prefix fits, otherwise leaves the initialized destination unchanged. `NativeBytes2026.from_hex` preserves constructor pairwise `strtol` parsing; `set_bytes_from_hex` preserves the separate setter’s strict hexadecimal-digit parsing. Invalid setter input is rejected before mutation rather than exposing a partially initialized native buffer. `NativeBytes2026`, `NotificationBool`, the native exception classes, `NativeParameter2026`, and the FlashWriterUtils functions provide bounded value semantics. `bind_parameter2026` selects exact native files and rows using stage-specific contact/protocol/CPU rules. Its immutable binding retains the original catalog bytes; alternate CPU selection derives only from the selected row, and validation reproduces source selection. Runtime CPUType changes require authenticated source-equivalent metadata state. The explicit classic `change_gateway` parameter stage selects CPU0 with `DLLFileNameForChangeToReprogGatewayMode` and phase3 version requirements, and requires its exact callable `ChangeToReprogGatewayMode` export. Classic prepare keeps the selected CPU parameter row while selecting its DLL/version from global CPU0. `alternate_cid_binding()` implements the exact empty-CID fallback selector: first alternate filename, separately selected first minimum version, no fallback when either native multi-value result is empty. It validates against the immutable original catalog and checks the exact alternate module/export/version. `rebind_getter_metadata` retains the original loaded parameter row while projecting only validated same-target live CalibrationFile state. `rebind_writer_metadata` does the same for the exact already-loaded writer, including its source-selected alternate CPU branch, before a PrepareRetry export. Neither method searches for a new parameter key after a failed export. More than one returned version is rejected as host memory policy because native7c20 has only one initialized260-byte output slot but loops over the returned total count. The raw getter helper retains the independently written `StartGetCID` param7 byte and returned identifier vector. Empty vectors select the source-named alternate module from the same loaded pool row. Exact module-specific process-output fields supply the byte; identifiers never imply success. The outer getter import owns the final identifier/hardware commit. `_control_has_ordinary_getter_return2026` admits this handoff only after the actual6f20 result and ordinary4be0 paired snapshot; phase alone grants no import authority. `NativeParameterBinding2026.dispatch` by itself remains the explicitly low-level direct-export admission and permits absent phase-version entries for isolated authored family checks; it cannot certify native ControlCommPhase acceptance. A real27 factory check additionally covers the22-event primary-empty/alternate-nonempty chronology. `NativeGeneralParameters2026` implements the distinct global `Parameter.ini` callback lookups and raises native lookup error2 when absent. `NativeFrontendParameters2026` separately binds the exact `Parameter.ini`, `CanIDTable.ini`/`RequestCANID` and `LogicalAddressTable.ini`/`LogicalAddress` sources used by frontend helpers. It retains immutable bytes and decoded rows and returns fresh mutable lookup objects; it accepts no caller CalibrationType or profile override. The normal table binding does not certify a later native SetForMazda replacement. The bounded direct CSV scanner follows native first-character delimiters, collapses doubled quotes even in unquoted fields, and retains native bare-LF multi-values. Their format/lifecycle coverage belongs to those modules. `ControlCommPhase2026` validates an exact native identity and implements the sync query and disconnect exports over the same runtime device. ## Raw CONTROL execution

The actual59ab0 import issues `NativeControlContext2026`, holding the post-rebuild FILE projection, native order, copied target vector, imported CID vector, ordered CPU cursor and worker-owned scratch arrays. Its engine/thread/runtime capability expires with that outer phase. Callback1 may synchronously move the outer FILE during a family export; it cannot change this held FILE or CONTROL cursor. Classic4c10 advances the cursor after each successful CPU, including its one-past-end store. Modern5c30 advances ordinary CPUs, but logical-node completion breaks before the store. P6's writer-local CPU remains separate.

`ControlParameterPool2026` owns the real constructor-zero CParameter array. Its allocation matches b980 process attach and survives helpers, failures and subsequent Execute calls until the loaded module is detached. Classic writer loading is incremental: load one slot, resolve its addresses, check module/version/exports, then load the next. All preflight finishes before writing. Missing/failed later loads leave already modified slots intact. Pooled bindings authenticate the exact selected slot, row revision, immutable catalog and held source; they do not reselect keys from the outer engine's current FILE.

`NativeControlExportTarget2026` freezes the actual row and entry module. Modern ordinary multi-CPU writes issue the next current-row/metadata projection only after the source cursor store while retaining the original module and preflighted address vector. This lets concrete family adapters consume the correct next archive without loading another DLL. The lexical engine family scope validates each issued target; it does not change P6's internal block/CPU plan.

The six helpers have distinct load and preflight rules. Classic8990 uses the current row's prepare address list with NULL callbacks and CPU0's DLL/version. Gatewaya250 preserves its incoming byte for an empty DLL and uses the actual gateway out flag to decide whether an invoked export replaces that byte. Modern9370 publishes callback24 before testing its result. Classic4c10 validates all rows and its optional retry/finish exports, then performs logging, callbacks1f/20 and source post-write stores in order. Modern5c30 uses false/false loader arguments for PrepareRetry/IsFinish, even if those row flags are set; Phase6 alone requires its void retry hook. Callback-aware resolver lookups use the canonical frontend table lazily; NULL-callback classic paths cannot acquire that authority.

Staged `ProgrammingReplay.run_bound2026` shares the original trace and runtime. Immediately after a real concrete runner returns, while its exact export capability is still active, it records the explicit primary BOOL or getter param7 byte. COMMON's typed helper catches preserve those saved locals if a later callback throws. CPass-derived catches write primary error plus fatal/native-fatal input and preserve error kind, driver status and failed. Host and other uncaught exceptions preserve identity and bypass the ordinary raw return. Auxiliary retry, finish and void exports do not overwrite the primary saved BOOL.

`_retry_control2026` implements3b90 against the actual live pool row and retained module. A successful PrepareRetry clears only primary and passthru error fields; failed, retry context, error kind and notifications remain independent. The confirmation/IsFinish path has its own failed/output/notification stores. The final classic DH tail calls `end_reprogramming_mode(0x3fc)` using the pool BASE; its catch-all covers only the actual virtual-call boundary and only the explicitly native error domain in the host port.

`bind_startup_session` authenticates the Control module and shared source/runtime, binds source dependencies and the constructor pool before gateway startup, and never dispatches a family. The same typed pool BASE capability supports constructor-empty and retained loaded rows without reselecting an old FILE key. Its parameter reads observe the current actual slot0 state; its held metadata and context ownership are validated separately. `_close_control_pool2026` releases only that engine's inactive owned module array, never an active helper or another engine's pool.

The ordinary4be0 tail exports the exact CONTROL interface snapshot. It does not import it into the engine. Only the actual getter's outer5a050 handoff imports that snapshot and then commits identifiers/hardware. Prepare/write outer5c2c0 does not import the interface snapshot. Both directions use source-issued pair snapshots and current signatures; no speculative reverse import runs in `finally`.

The worker owns count/percentage scratch. Decimal callbacks10/11 publish whole arrays; callback11 records the old global percentage vector before replacing it. Hex28/2f publish actual C25/C08 bytes into persistent engine caches after classic prepare, and their restore callbacks read those same caches. P6 progress changes do not advance CONTROL's cursor. Online controller reissue retains the same actual capture and elapsed-clock sink through `bound_online_controller2026()`.

## Verification and bounds

`RawControlStageMachineTests` covers same-Execute ordering, authentic pool/slot/module/receipt joins, distinct modern CPU archives, separate getter vectors/out bytes, typed versus host faults, retry and confirmation stores, Phase6 retained-module void calls, incremental preflight failure, source snapshot direction and startup-pool lifetime. Most orchestration controls substitute the concrete family runner boundary; the P5 getter proof additionally runs its real authenticated family adapter over authored primitive traffic and retains the same partial identifier vector for true and false process outputs. Family wire algorithms have their own module tests. These controls establish software behavior, not vehicle or adapter compatibility.

Run bounded method selections during development; the root integration owner runs the full common module and suite. Source-owned metadata validation and literal native domains remain mandatory. Unknown concrete-family BOOL/out-byte cleanup paths stay unknown. The alternate getter rejects more than one returned minimum-version entry as host memory policy: native7c20 initializes only one output slot yet loops over the returned total. Unsupported concrete adapters remain explicit software bounds. Full graph/device behavior still belongs to the dedicated modules; no OEM binary, vehicle or adapter is executed here.
