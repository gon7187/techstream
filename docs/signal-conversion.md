# Пересчёт диагностических параметров

`scripts/signal_conversion.py` восстанавливает числовую часть `DatMonCommon.dll`, SHA-256 `69b4984cff21632ace4e6b16829cb5197b68c169d3d2f3b0a832fca6ecf05118`. Синтетические проверки подтверждают нашу реализацию; физические измерения с ЭБУ ещё не выполнены.

## Связь исходных полей с потребителем

`GetDatMonSignalInfo.dll` RVA `0x186f..0x1881` выбирает PhyData по Freeze u16+60; RVA `0x1913..0x1925` выбирает Unit по PhyData u16+14. Freeze u16+62/+64 — включительные битовые границы.

`DataMonitorPhase3.dll` RVA `0x98c2/0x98c9/0x98d1` переносит PhyData i32+0/+4/+8 в runtime+0x4c/+0x50/+0x54; RVA `0x98f1` переносит режим знака PhyData[20] в runtime+0x48; `0x98f9/0x9905` — точность PhyData[21] в runtime+0x58; `0x9c20/0x9c25` — selector Freeze[76] в runtime+0x44.

В `Techstream.exe` SHA-256 `e6b7ab884c99a941d603251fb856a77a515639fdcd1d266e875cbd1abceb5e54` RVA `0xb0fe9..0xb1007` передаёт эти поля числовому evaluator VA `0xc553d2`. RVA `0xb1039/0xb104a` передаёт точность helper VA `0xc575e0`, который делит результат на `10^precision`.

## Числовые операции

Биты нумеруются MSB-first, диапазон включает обе границы. `extract_bits` проверяет границы переданного **полезного payload** и целочисленные DWORD-индексы; ширина не ограничена 32 битами. Смещённое 32-битное поле может занимать пять исходных байтов: `ff12345680`, биты 1..32 → `0xfe2468ad`. Статическая проверка CommandCommon RVA `0x9bf8a..0x9c035` подтвердила DWORD-сборку и unsigned32 вычитание baseline.

Сохранена особенность оригинала для поля уже восьми бит, пересекающего границу байта: RVA `0x9c00c` сдвигает первый байт в 8-битном `DL`, затем RVA `0x9c01a` сдвигает DWORD на `(end-start-7)&31`. Переполнение отбрасывает вклад первого байта. Поэтому `ff80`, биты 7..8 → 1, хотя обычная математическая MSB-выборка дала бы 3. При ширине более 32 бит каждый DWORD-сдвиг использует x86 count modulo32, а фрагменты объединяются OR; это не обычное усечение математического целого. Например, `010203040506070809`, биты 0..71 → `0x06070c0d`. Индексы байтов вычисляются в DWORD; 8-битного переноса индексов здесь нет. Регрессия перебирает все восемь смещений и ширины 1..32, проверяет пятибайтовую границу, поля 33/64/72 бита и unsigned32 underflow. Парный оригинал v12 RVA `0x6d2da..0x6d385` содержит тот же DWORD OR и DL-первый байт; это не расширяет отдельно ограниченный контракт `affine(bits=1..32)`.

Обычная ветвь `DatMonCommon` RVA `0x7480`: знак → signed64 умножение на A → signed64 деление на B с усечением к нулю → low32 плюс C с переполнением. Режим 1 — two's complement; 3 — sign-magnitude; остальные — unsigned. Деление выполняется, когда `(B & 0xffffffff)>1`: 0 и 1 пропускаются, отрицательные B делят. Пример `raw=3,A=-1,B=2,C=7` даёт 6.

Диспетчер RVA `0x7505` имеет отдельные ветви: selector 6 — кусочное обратное преобразование, 24 — порог 3000, 7–11 — сериализация битов с особым знаком и signed32 арифметикой, 19 — упакованные quotient/remainder по 60. Они перенесены отдельно. Остальные selector проходят обычную числовую ветвь; это не доказывает, что каждый режим отображается обычным числом: текстовые PatternDisplay/BCD/даты требуют своих потребителей.

`format_scaled` воспроизводит равную исходную/экранную точность `CommandAPI.dll` RVA `0x66e0`: десятичная точка без округления к ближайшему, положительное число с дробью имеет ведущий пробел. Ограничены precision 0..9 и signed32 без INT_MIN; неподтверждённые крайние случаи отклоняются.

## Граница live-режима

`ChangeSignalLSB` может изменять коэффициенты для конкретного ЭБУ. Транспорт также заменяет исходные битовые позиции полученными response descriptors (Phase3 RVA `0x89cd/0x89d2`, `0x8ab9/0x8ac2`). Поэтому базовые DDB-поля нельзя безусловно применять ко всему J2534 сообщению. Нужны выбор exception-варианта и правильная граница payload. UI показывает определения и сохраняет эту границу; не подставляет вычисленные числа как реальные показания.

Точные исходные SHA, инструкции и 12 связных оригинальных Freeze/PhyData записей: `analysis/evidence/fullport-scaling/`. Проверка: `python -m unittest discover -s tests -p test_signal_conversion.py`.

Независимая REA-проверка оригинального affine worker при интеграции: `ev_11fae3985ea070cd5bf2ef1c0425222af747c7e1d3ab645cd701fe6bfe082dd9`, bundle `analysis/evidence/native-scale-integration.json`. Извлечение сохраняет unsigned low32 до следующего этапа — signedness применяется внутри преобразования.
