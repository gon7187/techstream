# CUW2026 persistence

`scripts.cuw_persistence` reconstructs the recovered CUW2026 `CUW.dll` recovery storage and notification handler. It accepts immutable caller-supplied calibration bytes or an exact parser-issued `LargeSource2026` backing view, and an explicit absolute output directory. It never opens a pathname from imported recovery information, accesses a vehicle, executes vendor code or calculates authorization material.

`CUWPersistence(output_root, ReproInfoState(...))` creates one actual `programming_2026_common.NotificationBool(False)`. The CUW engine owns this persistence object and shares its exact `.notification` instance with each controller. `bind_engine_source(actual_engine)` binds the concrete engine source validator. Source-bound handlers and persistence capture validated state snapshots and use the same immutable bytes or authenticated backing view for planning and output, preventing later mutation of a source field from substituting unrelated bytes. Assigning true runs the recovered `309d0` handler: create the `Save` cache when it has not already been loaded or logged, mark writing, write `RecoveryInfo.ini`, then mark logged. Assigning false changes the notification value without clearing stored recovery state. The separate `.last_block_notification` is the actual `30b50` object: both true and false assignments copy the owned object value into `writing_end_block` and persist when logged. Copying its handler to another notification does not change the owned value. A failed true handler leaves the notification true and does not claim that persistence completed. `update_cpu(index)` updates the source CPU field and persists it when logging is active. `update_divided_image(index)` implements callback45 (`58e80`) with the same logged gate.

The storage codec implements `21660` and `1f0e0`: native section and key ordering, native byte strings represented reversibly with Latin1 (no assumed Windows locale), CRLF separators without a final newline, and the native two-character nibble encoding. The low two bits of each encoded character carry non-semantic noise; generated output uses zero noise. `parse_recovery_info` retains the original encoded bytes exactly in `RecoveryDocument.to_bytes()`. High bytes are shielded from Unicode whitespace classification during INI parsing and restored before exposing fields. A Python field character U+0000–U+00FF represents the identically numbered native byte; callers with Unicode text must supply its actual source encoding rather than assume a Windows code page. Known fields are validated and indexed rows must be complete. Unknown fields survive document round trips. Re-encoding typed state emits the fields written by the recovered native writer.

`load_recovery_state(document, attachments, cpu_capacity=...)` decodes storage fields using explicit saved-path-to-source attachments. The capacity must be the actual shared `CommonDefinitions2026.num_cpu_maxnum`; assembly, availability and blank-ECU vectors are resized accordingly. `CUWPersistence.import_recovery` stages these attachments and the original encoded document beneath the selected output root, relocates in-memory cache paths, and marks loaded after successful storage. This is storage import and supplies no ECU recovery authorization.

`replace_calibration` implements the whole-file association update from `23b10`, retaining existing CID/address/assembly metadata. When logged, it writes the replacement cache and recovery document before removing the old cache. This host ordering deliberately preserves the recoverable old file until replacement is durable; native code deletes the old file first. `delete_recovery` attempts all owned cache files and the INI, then resets state as `38880`/`23630` do. Ordinary deletion failures are collected. Host cancellation or deadline stops immediately and retains live state.

The small immutable-byte input limit remains 64 MiB. Large calibration persistence uses the existing parser-issued `LargeSource2026` (300 MiB through UINT32_MAX), with its pinned descriptor and original pathname identity checks. `calibration_source_identity` returns bounded size and the authenticated source digest; the engine additionally requires the same container object as its parsed metadata. Cache copies read 1 MiB chunks, hash the bytes actually written and verify the source again before atomic replacement. Existing caches are compared by streaming size/digest rather than loading their contents. Aggregate source size is bounded to UINT32_MAX. Persistence borrows the source container: its owner must keep it open until persistence completes; persistence never closes or removes the original. Cancellation, source mutation and write failure remove uncommitted temporary files. Already committed cache files remain available if a later recovery-document write fails.

All output files are created with mode `0600`, temporary files use exclusive creation, and writes use fsync plus atomic replacement. Directory traversal follows no symlinks. An unrelated existing output, a symlink, a changed target during commit or replacement of the chosen output or Save directory is rejected. Owned outputs retain their last committed content hash; external changes are preserved and reject subsequent overwrite or deletion. Clock observations must remain finite. Cache basenames are extracted from original source labels; source labels are never used as read paths. Directory and target identity/content are rechecked after callback boundaries before committing or deleting. Existing output is preserved on malformed input or collision. Callback injection is limited to fault testing and cannot return a fabricated persistence success.

The recovered programming-log export `65a40` returns a caller-owned ABI buffer; it does not write a log file. `build_programming_log_info` reconstructs its availability gate, CPU progress, percent and `4b1e0` communication-error formatting. `ProgrammingLogInfo.to_bytes(previous)` writes the exact `0x2160` layout while preserving untouched padding and string tails. The caller supplies actual engine status, captured communication bytes and voltage observations. When alternate progress is active, its CPU, offset and base are separate inputs; percentage lookup continues to use the regular CPU index. No log filename or file format has been invented.

The format and handler are specific to the reconstructed 2026 engine. They must not be substituted for CUW12/18 recovery files without separate source evidence. Public reports contain counts, state flags and bounded operation names, and omit source paths, VIN, CID text and communication buffers. Tests use authored values, including an authenticated sparse 300 MiB original: copy/import/delete, less than 4 MiB traced allocation during streaming output, cancellation cleanup, forged provenance rejection and source mutation before commit. Physical behavior remains unconfirmed.

Run `python -m unittest discover -s tests -p test_cuw_persistence.py -v` from the repository root. Native anchors are retained privately under `analysis/evidence/no-car-21/source/CUW.dll/`; the field-key extraction evidence is under `analysis/evidence/no-car-84/`.
