# Нативное чтение баз Techstream

`scripts/diagnostic_db.py` читает оригинальные DDB средствами Python, включая распаковку. Исходные DLL не загружаются. Проверены все 1422 файла NA/EU/JP: 25 655 секций, 82 сжатые секции, 53 уникальных сжатых содержимых; ошибок нет. Результат: `analysis/ddb-native-validation.json`.

## Формат

В заголовке: kind по смещению 8, количество слотов по 9, `DiagTool DataCtrl\0` по 10, версия LE u32 по 28. По 36 начинается массив абсолютных LE u32 смещений; ноль означает отсутствующий слот. Первая секция начинается сразу после массива. Неинтерпретированные поля заголовка сохраняются в оригинале.

Версии `0x0100032f`, `0x0100030c` и `0x01000225`: заголовок секции `<BBII>` — номер слота, флаг сжатия, число записей, размер сохранённых данных. Версия `0x01000137`: `<BBHI>`, число записей u16. Секция точно занимает интервал до следующей или до EOF. Проверяются номера, флаги, границы и точное потребление.

`0x0100030c` — версия ресурсов Techstream 12: её возвращает исходный `KgpDataCtrl.dll` по RVA `0x30e1a` (SHA-256 `ac93400c60a22878827ca38f028a0a724a6baae068cd0ec8041496997eda6749`). Поддержка версии контейнера не подразумевает одинаковые схемы всех таблиц разных выпусков: семантические читатели отдельно проверяют ширину записей.

Сжатые данные: `<IB>` — размер результата и побитовое OR всех распакованных байтов, затем LZSS. Кольцо 4096 байт, начальная позиция `0xfee`; флаги от младшего бита, 1 — литерал. Ссылка: `offset=a|((b&0xf0)<<4)`, длина `(b&15)+3`. Перекрывающиеся ссылки допустимы. Ссылки в незаписанную область, несовпадение длины/checksum и лишний хвост отклоняются. Лимит файла — 64 MiB; отдельный общий лимит 64 MiB применяется к сумме распакованных секций. Размеры всех секций проверяются до распаковки. На проверенном корпусе из 4055 оригинальных DDB максимальная сумма — 26 655 659 байт.

Языковая секция 0: `count` записей `<IH>` (смещение и байтовая длина), затем UTF-16LE pool. Смещения непрерывны, строки завершаются NUL, весь pool потребляется точно. **Строковые ID начинаются с 1, ID 0 означает пустую ссылку.** У U-ресурсов есть дополнительная секция; она сохраняется, `Language` читает секцию 0.

Ссылки файлов ЭБУ берутся из EcuCategory, без сопоставления по похожим именам. Разные записи одного ключа могут зависеть от exception-правил и выбранного автомобиля; `signal_variants` сохраняет все варианты. Справочник не сообщает, какие ЭБУ физически установлены.

`Database.records_for_key(slot, key, language)` возвращает **все** совпадения с сохранением порядка. Это применимо к названиям автомобилей, support и active-test определениям, но не является проверкой совместимости. Выбор default/exception записей и PidBit/DidBit gates реализован в [профилях автомобиля](vehicle-selection.md). Используйте выбранный `VehicleProfile`, чтобы применить native порядок и условия обработки; простой поиск по ключу их не применяет. Доступность активного теста определяется [phase-specific List/Init](active-tests.md) с явными наблюдениями поддержки. `Sup*` — определения ресурсов, а не ответ физического ЭБУ о поддержке.

Дополнительные адреса в том же `KgpDataCtrl.dll`: ActTest stride `0x1000640c`, ключ/selector `0x100064b8`, exception ID/flag `0x10006443/0x1000647f`, имя `0x10005e4a` (ID по +32), short-name pointer `0x10005fa4`; SupFreeze `0x1004b429/0x1004b45e/0x1004b496`; SupPid `0x1004c467/0x1004c49c/0x1004c4d4/0x1004c50a`; SupDid `0x1004b0d7/0x1004b10c/0x1004b144/0x1004b17a`. VehicleName stride `0x10054964`, имя `0x100546bb`, lookup key `0x10054849`. ExceptionFindId stride `0x10035c9b`, mask reader `0x1003588d`; ExceptionProcessId stride `0x10036337`, ключ `0x10036119`.

Повторная проверка всех 1422 DDB с новыми схемами завершилась без ошибок: SupFreeze 3199, SupPid 4785, SupDid 1959, ActTest 13719, ExceptionFindId 155, ExceptionProcessId 384242, VehicleName 9031 записей. Это подтверждает размеры и строковые ссылки в данном корпусе, но не физическую поддержку или полноту интерпретации.

- `KgpDataCtrl.dll`, SHA-256 `e5235bc0c241c6a450fe461031eed0915675032b1db994bd54d98818fac88aa9`: чтение секции VA `0x100373ca`; строковый lookup `0x10050383` вычитает 1; DTC `SetRecString 0x1002ec9d`, ключ `0x1002f104`; EcuCategory `0x10032e84/0x10032f00/0x10032f43`.
- `DataCompress_DT.DLL`, SHA-256 `469d28871f46c291e8772576965c902ee2996246e9765e0c409e042bcda4eed1`: wrapper `0x10001e50`, LZSS `0x10001bd0`, OR checksum `0x10001db0`.
- Коэффициенты и связанный потребитель: [signal-conversion.md](signal-conversion.md).
- Полные инструкции, mapping, корпуса и SHA: `analysis/evidence/fullport-ddb/`. Независимое REA подтверждение адреса PID-записи: `ev_e71d06ea1f4bc0865a395e9d96b9e60d88aa6cc6b866da2aae039287e1e64462`.

Малформированные заголовки, ссылки, LZSS и строковые ID проверяет `python -m unittest discover -s tests -p test_diagnostic_db.py`. Формат ресурсов восстановлен шире семантики: остальные поля, правила выбора автомобиля и исполнение диагностических команд ещё требуют переноса.
