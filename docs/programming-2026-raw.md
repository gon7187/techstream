# CUW2026 generic CAN operations

`scripts/programming_2026_raw.py` reconstructs five source-identified 2026 generic CAN modules and their six callable exports over bounded injected primitives. Importing it opens no device. An older filename never selects a CUW12/18 implementation.

The assigned exports are SoftwareInfo `StartGetCID`; ReproStd `StartPrepareWrite` and `StartFlashWrite`; PowerTrain `StartFlashWrite` and `PrepareRetry`; and Solar `StartFlashWrite`. `bind_native_context` joins native2026 CUW metadata, exact parameter sources and typed communication-address resolution; `execute_context` selects the corresponding controller. Source identities, C/assembly hashes and indirect dispatch tables are recorded in private leaf73 evidence. G2/G3 remain OPEN pending full source reconciliation and factory integration.

SoftwareInfo sends literal `1A 88 00`, reads the nonzero identifier vector, then sends `1A 88 xx` for each item. It preserves partial results, both native full-message offsets, the 16-byte/NUL/trailing-space rules, `SoftwareInfoIDByteNum`, the 34-slot query-address cap, and BS1/BS0 for extended addresses or native ECU kind `38`. The native callback12 binding is mandatory and preserves listing/detail skip decisions, including the second observation when listing returns false. Independent host cancellation raises `InterruptedError`. The host runtime also releases the listing filter when native callback12 skips the listing; original1790 leaves that filter allocated on that branch.

Classic Solar/PowerTrain writers bind the actual archive, password selection and a programming/finish pair from consecutive records returned by ONE native FlashWrite address selector. There is no separate Finish selector. Solar reloads the secondary catalog using the separate engine string observation `native_engine_cpu_type`; it is not inferred from the current calibration CPU. Dynamic next-CPU and finish-response flags come from global `Parameter.ini`. Shared erase/write/verify/security primitives are the individually recovered actual2026 `CommonFlash2026` implementation.

PowerTrain retry implements native command05, timeout handling, error13/15 dummy payload lengths1024/256, response draining, repeat and CPUtype22's5000ms wait. Ordinary PowerTrain writing includes blank checking, native alternate-CPU parameter reloads, memory requery, progress and finish selection.

ReproStd preparation implements all six native virtual methods: periodic tester-present frames, communication setup, DTC suppression, diagnostic masking, programming session and security. Success deliberately retains its periodic resource for the caller's subsequent programming stage; failure/cancellation cleans resources acquired by preparation. Supply original `secret_info` and `cuw_engine` attachment bytes for the authenticated private SecretInfo binding. Gateway operations require their concrete source-bound DH/Suzuki utility objects when calling `run_repro_prepare` directly. `execute_context` constructs those objects from exact original `dh_utils`/`suzuki_utils` attachment identities; root factory routing remains under independent integration review.

ReproStd writing implements the native virtual fingerprint/download/transfer/routine/reset/communication-finish methods and logical block order. Nonzero delta images transfer with selector `21` and run verification; zero-length delta images skip both without dividing progress by zero. Source-scoped gateway-end and filter-cleanup exceptions preserve the native BOOL; cleanup failures are reported separately and failed runtime ownership is retained. Getter Disconnect and original receive-timeout restoration remain outside these suppression scopes. An active host exception retains its original identity when cleanup also fails; cleanup exception types are appended as notes. The `tester_info` attachment contains32 original engine tester-information bytes. The SYSTEMTIME primitive supplies eight Windows uint16 fields. Cryptographic providers receive explicit seed/key material and return bytes, never a Boolean asserting business success. The scoped2026 request builders preserve source2810/2b60 zero-length behavior and original CBytes widths, ordered overlap, zero padding and fixed wire truncation for address/length/CRC/authentication fields; older nonzero-only request builders are not used for this contract. The scoped block-size decoder also preserves2810 reads from the zeroed receive buffer, including a partially supplied declared width. The fingerprint helper reused from the earlier implementation is separately reconciled to actual2026 source3560; its version label is not compatibility evidence.

Large source-backed archive descriptors are rejected before I/O in ReproStd: native3180 only implements direct memory copy or MakeSendData and has no P6/Ethernet stream-reader branch. The native selector/unsafe-input closure for this join remains OPEN; a reader from another family is not substituted.

Run authored checks with:

```sh
python -m unittest discover -s tests -p test_programming_2026_raw.py -v
```

Tests use authored CUWs, parameter rows and replies, including imported input through `J2534Device2026` and literal typed PassThru chronology. Portable preparation tests inject an explicitly test-scoped SecretInfo capability; a separate negative control verifies that production rejects an unissued client. A private source-input control loads original SecretInfo/CUW artifacts and composes actual DH gateway AES authentication with imported preparation, without the synthetic issuer. This does not claim OEM authorization or secret equivalence. Source/native ABI reconciliation, mixed-CPU branches and complete fault controls remain under independent review. Physical timing, adapter behavior and ECU programming remain `PHYSICAL_UNCONFIRMED`.
