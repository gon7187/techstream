# CUW2026 J2534 host layer

`scripts.j2534_2026` contains an authored Python port of selected native
`TCUWJ2534DeviceIF.dll` client algorithms. It does not load a driver or open an
adapter, network endpoint or vehicle.

The exact source module SHA-256 is
`d29da8dbdb7f08c6ff301e9f5859a9f407e3c9af68a6496410e8580ceae8bb08`.
The separately identified `TCUWCommunicationAddress.dll` SHA-256 is
`fd18f710af60ba9a1be979831ac2e878739ea577f3a1ba0d6edf0d7ce9b1e12d`;
its nine address-selection strategies are ported from the separately authenticated
2026 C/assembly. Legacy versions are not interchangeable.

The implemented J2534 paths preserve:

- constructor receive/send timeouts (0/1000 ms), padding enabled;
- native indication mapping from the low five `RxStatus` bits (RVA `2b80`);
- wired 0404 open/connect protocol flags and baud choice (`42d0`, `2550`);
- CAN FD configuration parameter order and optional parameter (`54e0`);
- transmit receive-buffer clear before writing, protocol/flag mutation, matching
  transmit indication consumption, and pre-mutation last-message history
  (`6770`, `6950`, `44e0`, `5670`);
- address/status read selection, including a fifth address byte (`48c0`), and
  normal multi-address response collection in arrival order (`4a40`);
- exact pass/block and flow-control mask/pattern/message construction (`57f0`,
  `5920`), including independent padding, 29-bit and address-extension flags;
- periodic-message padding differs from regular writing (`5be0`);
- programming-voltage transitions only for native enable/disable sentinel
  values, and state mutation only after success (`5710`).

`NativeMessage` is immutable and retains native protocol/status/flag/timestamp
fields. A provider receives one primitive operation dictionary and remaining
seconds, and returns `PrimitiveResult(status, value)`. It supplies low-level
PassThru/OS operations only. Checked native API calls raise `NativeTransportError` with the exact nonzero
status. Native `Disconnect`, `Close`, unload and raw 0404 synchronous writes
ignore their returned status, as the recovered source does; their return does
not prove that a real driver released hardware. Reads return a bounded tuple of typed messages; successful
zero-message reads remain zero results for raw wrappers; addressed CAN selectors
retry within the host deadline and call budget.
Acquired handles are retained before cancellation/deadline checks, including
zero-valued native handles. `disconnect()` uses a separate cleanup allowance;
checked release failures retain state so cleanup can be retried. Successful
handle releases are recorded before post-provider timeout checks, avoiding
repeat close of a handle already released.

The existing shared diagnostics consumer can use the host layer directly:

```python
from scripts.j2534_2026 import J2534Device2026
from scripts.programming_2026_common import NativeRuntime2026, CanDiag2026

# provider is an injected offline/replay primitive provider supplied by the caller.
device = J2534Device2026(provider)
device.open()
device.connect(6)
runtime = NativeRuntime2026(device.primitive)
diagnostics = CanDiag2026(runtime)
```

Provider operations include `passthru_open`, `passthru_connect`,
`passthru_ioctl`, `passthru_read`, `passthru_write`, `passthru_start_filter`,
`passthru_stop_filter`, `passthru_start_periodic`, `passthru_stop_periodic`,
`passthru_voltage`, `passthru_disconnect`, `passthru_close`, plus low-level
wait/lock/unlock and version device-selection primitives. Providers must honor
remaining deadlines; Python cannot preempt a blocked provider callback.

Additional source-audited paths cover 0500 scan/get-next/open/resource connection,
UDP/TCP logical-channel descriptors and routing, the two-stage TCP header/payload
read and reversed request-address correlation, exact ordered shim/wrapper symbol
loading, driver version metadata, and temporary device-info open/close cleanup.
All DLL operations remain injected low-level primitives; no DLL is executed.
`DriverMetadata2026` plus `connect_native` runs the source ownership/load/probe/
open/connect path. The raw `open`/`connect` pair models prebound API calls; the
shared bridge selects `connect_native` when driver metadata is supplied.

Optional `MessageHistory2026` models the native last-message pointer. The
constructor's pointer is null, so it records nothing until a sink is attached.
Disabling recording retains the preceding sink value. Wireless/DSTi probes use
raw symbol tokens and raw `DeviceInfo2026` fields; provider callbacks never
choose whether a device is wireless or supports CAN FD.

`GetDeviceInfo` preserves native exception/output ordering: device name is assigned
first; `ReadDeviceVersion` copies its three zero-initialized buffers before checking
status. Typed version faults retain these strings in `.versions`; the outer info
getter catches native faults, cleans only resources it opened/loaded, and returns
the written or preceding output strings. Optional `previous` supplies native in/out
string values. Python provider errors and cancellation remain host failures.

Wireless probes preserve their distinct handlers: a typed loader fault continues
into the selected probe; DSTi Open failure returns false after reset/free; Mongoose
uses raw query output fields even when ControlIO raised. CAN-FD support probing
retries failed Open(2) as Open(1), returns false on fallback success without issuing
the query, rethrows a second Open fault after cleanup, and returns false on query
fault. Loader faults precede these handlers and propagate. No provider decides
these outcomes.

`read_indication()` without an address performs one driver read; zero count uses
the zero-initialized RxStatus and returns indication3. `read_after_indication()`
models native ReadMsgs4840: its native-exception handler discards a typed error
from the first indication read and then runs the second raw read. Host cancellation,
deadlines and malformed/failed Python providers propagate distinctly.

`start_sync_periodic` starts a real daemon thread by default. It preserves local-time
midnight handling and unsigned backwards-clock subtraction, poll delay, timestamp
placement around post-send delay and mutex unlock, raw 0404 write-status ignoring,
and checked 0500 queue/TCP writes. Foreground filtering and transport lock operations
share the injected native mutex. Stop signals an event and joins the thread before
closing its mutex. Transport exceptions reach the foreground owner after cleanup.
`background_workers=False` enables deterministic replay through `sync_step`.

Ownership uses a separate real worker and two manual-reset events. The worker owns
`TECHSTREAM_MUTEX_J2534`, tries waits of zero then 500 ms, signals readiness, waits
for release, and releases/closes the mutex from the acquiring thread. Cleanup joins
within its own allowance; a blocked provider leaves the live worker retained and
reports a timeout. Providers must implement the supplied OS primitive semantics.

`export_data(previous=None)` and `import_data(NativeInterfaceData2026)` implement
native RVA27c0/3020 transfer. The typed record retains exactly 25 function tokens,
current and per-version driver strings, open/connect flags and IDs, timeouts, the
counted SIL filter prefix, voltage/padding, shared ownership thread/events, wrapper
handle and history pointer. Native stale channel IDs survive disconnect in the
export record while the host ownership field becomes empty; Clear resets them.
A terminated ownership-thread slot also remains export-visible after failed
acquisition/release/Clear; a new worker replaces it, while joining an active worker
clears the slot. This stale observation does not imply active mutex ownership.
Previous output slots survive when native export does
not write them. Import copies strings and aliases external thread/event/history
references. It refuses to overwrite a receiver's owned handles. Logical channels,
synchronous worker, loaded flag, history-enable flag and previous-send time are
absent from the native record and remain receiver state. Provider-only worker
exceptions share diagnostics through the existing release-event reference; this
adds no native transfer field. Native ownership code has no exported error member.

`DriverMetadata2026` supports the native empty descriptor, setters, assignment and
clear. Selection copies its strings. Private C++ copy constructors remain unavailable
through the public authored API. Version switching selects the corresponding driver
record and reconnects through the complete ownership/load/probe/open/connect path.
Checked API errors retain legacy `.code` and expose separate `.native_error_code=1`
and `.passthru_status`; native non-API errors retain their primary enum and no API
status. This follows TCUWException RVA2180/2430 rather than conflating both fields.
Multi-read exceptions expose native `returned_count=0` and `first_data_size=0`
from catch-all RVA4fe9. Their `.messages` are authored partial-observation
diagnostics; underlying data/extra-index values are retained, and do not represent
a successful native output count.

The `NativeRuntime2026` bridge automatically binds `cleanup_primitive` for bounded
restoration and release after cancellation. Cleanup does not modify operation
dictionaries and rejects transport writes. The explicit `switch_connection` restoration
capability may reconnect only the requested protocol within its cleanup deadline. Batched write inputs
accept `messages=tuple[bytes,...]` or `data=tuple[bytes,...]` with exact native counts;
partial acceptance is returned unchanged. A newly acquired filter hidden by an
inner cancellation/deadline is rolled back before the bridge raises; preceding
filters and the channel remain intact. A failed rollback retains device ownership
and annotates the original error. Ethernet logical channels, TCP, control
I/O and 0500 synchronous periodic operations use the same primitive boundary.

`CommunicationAddress2026` accepts native parameter strings, node DiagIDs,
`ResponseCANID` table values, Suzuki header IDs and shared CID-result history.
`resolve` runs the literal named strategies in order, accumulating records and
stopping on the first false result. Unknown names preserve the preceding result.
Records contain two/two-byte or three/three-byte IDs and the address-extension
flag; `headers()` emits corresponding four/five-byte J2534 headers. CID-prefix
matching is anchored at the beginning; `*` uses the whole CID count. Respond-CID
replication repeats the entire accumulated vector. Result-history matching uses
request ID plus extension flag, while history insertion retains duplicates.
CAN-ID table failures retain preceding records and report false. LocationID
uses bytes 2:4 for request, 0:2 for response, and bytes 6:8 select `0720` versus
`0740FE` gateway. Host limits reject malformed/oversized metadata before native
unsafe-copy behavior could occur.

Tests: `python -m unittest discover -s tests -p test_j2534_2026.py -v`.
They include `CanDiag2026` through the actual host bridge over typed primitives,
with a response-pending reply followed by a positive response. All observed
execution is authored offline execution. Physical behavior remains
`PHYSICAL_UNCONFIRMED`.

The constructor exposes positive uint32 `max_calls` (default 65536) and
`max_cleanup_calls` (default 1024). Each successful mutex lock reserves exactly
one unlock attempt; ordinary paired releases have a separate diagnostic counter
and preserve the shutdown reserve. A failed release consumes its reservation;
retries consume the bounded cleanup budget. Counters are never reset to extend a
transaction. Large callers must choose their normal-call budget from image geometry.

Direct native 0500 entries retain their separate behavior: `connect_0500` does not
acquire ownership or reset message history; `control_io_0500` retains its explicit
resource argument. `switch_connection` preserves history and uses the classic
Connect slot even when the selected version is 0500. Empty constructor device and
logical IDs reach the provider as zero. `set_current_driver` copies only current
strings; selected version records are separate copied objects.

Native CAN FD configuration errors perform full Disconnect, core reconnection,
then configuration with the false flag. Device probes preserve their native catch
boundaries, temporary-resource flags and copy-before-status metadata. Native SIL
ReadMsgs discards one indication read, swallows a typed native fault from that
first read, and performs its second wrapped read; explicit host failures remain
visible. Successful writes retain their accepted count when only the subsequent
TX indication throws a native error. A 0500 periodic native per-frame fault advances
to the next frame. TCP header backing capacity and reported count remain distinct;
a zero-count header may decode a zero-size second read.

Host containment preserves a primary guarded-body failure if mutex release also
fails, and attaches the release diagnostic as an exception note. A lone release
failure remains visible. This is explicit host failure policy; it does not invent
a native error from an ignored Windows ReleaseMutex return value.

`wrap_write_messages` exposes native6770 independently of full `write_messages`:
it clears RX and applies protocol/flags, returns the accepted count, and performs
neither history mutation nor TX indication consumption. An empty tuple reaches a
native zero-count write. UDP discovery byte-buffer reads use native literal timeout
zero independently of the configured timeout; single-message queue counts and
provider returned counts are bounded by the supplied typed message capacity.

Full and wrapped write methods accept an optional requested `count` separately
from backing message capacity. Full WriteMsgs with count zero retains a valid first
backing message for native history and indication behavior; zero selected messages
are not mutated. Raw read count zero reaches the primitive API. Full ReadMsgs count
zero still consumes its first indication read before the zero-count wrapped read.
Native catch-all branches recognize only explicit native-domain exceptions, including
`NativeException2026`; unrelated provider errors retain their original identity.

`NativeReadBatch2026` keeps observed backing messages separate from the driver's
reported count. Providers may return this type or the existing tuple (whose length
is the count). `read_messages_result` preserves both; `read_messages` returns the
reported prefix for compatibility. `read_specified_result` returns the first message
and independent count, while `read_specified` retains its existing message result.
ReadSpecified48c0 compares the freshly zeroed backing header without a DataSize
gate; addressed ReadIndication44e0 requires sufficient DataSize. Explicit backing
may therefore match even at reported count zero. Zero-filled tail comparison does
not change the returned data length or count.

Host input-domain restrictions are explicit: logical connect requires an owned
parent and an unused target slot, and channel-dependent convenience operations
require a connected channel. Native raw functions can instead pass zero/stale IDs
or overwrite an existing slot. Established raw ID zero remains valid. Complete
reachable caller closure for these additional ordering bounds remains under review;
unrestricted native ABI state parity is not claimed.

The primitive bridge exposes `read_messages_result` and
`read_after_indication_result` for exact backing/count observations. Existing byte
conveniences observe the first backing Data even when count is zero, as their native
callers inspect the supplied message buffer. Empty backing still yields empty bytes;
no output count is inferred from the byte length. Consumer60 confirmed actual source
parent/channel ordering at PrepareDiagComm17e0/helper19f6, reconnect258d and
Finish1580/15d8/15f9; its paths establish parents and finish before reconnecting.

The battery consumer can compose `read_device_version()`,
`control_io(1, ((1, 0),))` and `control_io(3)` over the existing typed provider.
The last operation retains the raw DWORD; unsigned conversion and division by 1000
belong to the source consumer. The 0500 path retains its native resource descriptor.
The consumer's native probe/failure acknowledgment handlers remain under review;
normal raw primitive parity does not establish their closure.

The bridge exposes `get_can_frame_padding` as the actual instance flag, so raw
RxStatus consumers can apply the native indication mapping for status 16. It also
exposes typed `start_periodic(message=NativeMessage(...), interval=...)` and
`stop_periodic(identifier=...)` through existing native 5be0 behavior. Runtime
acquisition owns the returned identifier, including zero. If inner cancellation
or deadline checks hide a fresh identifier, the bridge stops only that acquisition;
a failed rollback retains device ownership and annotates the primary failure.

`disconnect()` uses the shared host cleanup containment policy: all later release
stages are attempted after a provider or worker exception, the exact first error
remains primary, and subsequent failures become notes. Each successful stage
updates only its own ownership; failed stages retain their handles. This is host
failure containment, beyond the native ignored API-status behavior.

`NativeMessage` is an immutable value contract. Native 5be0 mutates the caller's
PASSTHRU_MSG protocol and flags before calling the driver; this API instead supplies
a prepared replacement to the primitive provider and leaves the original value
unchanged, including on failure. Wire fields match the source. Native writable
buffer aliasing is not provided; callers needing to observe that mutation require
an explicit output contract and separate source/consumer review.

An active receiver accepts an equivalent re-import only when transferred values
match its current export and provider/thread/event/history references are identical.
This is a no-op that preserves unexported local resource owners. Direct changed active state is still rejected. Source-issued pair transfers below
provide the explicit peer path; complete source and consumer review remains open.

`J2534InterfacePair2026(engine, control)` binds exactly two distinct views with the
same provider, clock, cancellation, host budgets, background policy and initial
driver metadata. One peer must initially own no resources. `validate_views()`
checks role and capability identity. The pair shares the host state lock and
thread-local cleanup capability, aggregates both lower-level call budgets and
uses the earlier normal deadline. Native view flags remain independent.

```python
pair = J2534InterfacePair2026(engine_device, control_device)
wire = pair.export_from(pair.engine)
pair.import_into(pair.control, wire)
# The control view runs the selected source phase and may close shared handles.
returned = pair.export_from(pair.control, previous=wire)
pair.import_into(pair.engine, returned)
```

The pair retains only the latest issued snapshot per source view. Import requires
that exact object, an unchanged field fingerprint and the same current source
export. Any source primitive call invalidates its issued snapshot. Forged copies,
foreign views and obsolete snapshots are rejected. Only this internal issued path
can replace active transferred state; local sync/logical/periodic and non-SIL
filter ownership remains local as required by the native transfer layout.

A host-only ledger tracks per-view device/channel and shared module/driver handle
generations. A successful raw release retires that generation, so later stale
peer cleanup does not call the provider again. Failed API status or provider
failure does not retire it. Reused numeric IDs create new generations. This
containment adds no native DTO field and does not synchronize peer flags; only
literal import or native opened-byte callbacks do that. A terminated shared
ownership worker is not signaled again, following native 5080, even if a peer
already closed its shared event. Whole-module acceptance remains open.

Child-resource owners can bind cleanup to the actual physical channel generation:
`device.interface_pair` is read-only; `pair.channel_lease(device)` returns a
`NativeChannelLease2026` issued for that view's proven current generation. Imported
views of the same physical channel receive the same lease object. Constructing or
copying its numeric fields does not grant authority: all queries authenticate the
exact issued object against the pair's cache.

Before child cleanup, `pair.channel_lease_retired(lease)` reports a successful
release recorded for that exact physical channel generation or its known acquired
device generation. The channel-to-device association comes from the actual Connect
input before its callback; a reused numeric device ID grants no authority over an
older generation. A runtime may retire
only entries stamped with that lease. Otherwise
`pair.validate_channel_lease(device, lease)` requires the same live current
generation; a different or unproven parent must retain the child entry and reject
cleanup rather than send its old identifier on a reconnected channel. A failed
Disconnect alone does not retire a lease; a subsequent successful Close can retire
that channel through its exact known parent. A failed Close cannot. Reuse of ID zero creates a distinct lease.
These observations perform no provider calls, consume no call budget and change
no native flags. They remain available during cancellation and preserve a successful
release even when an earlier native fault remains the primary disconnect exception.

Physical retirement applies to driver-owned filters, PassThru periodic messages
and logical channels. Synchronous periodic transmission owns a separate local OS
thread and mutex (native 6220); those fields are absent from typJ2534IF transfer.
`stop_sync_periodic` and `stop_sync_periodic_message` therefore retain their actual
acquisition-view cleanup and must stop/join/close local resources even when the
channel lease is retired or its numeric ID has been reused. A retired physical
parent never authorizes discarding an unclosed local worker.
