# Techstream для Linux

[English](README.md) · [Начало работы](docs/getting-started.md) · [Участие](CONTRIBUTING.md)

Независимая нативная рабочая область Linux для исследования диагностики Toyota/Lexus: Python, GTK4 и libadwaita. Выбор автомобиля по локальным определениям, просмотр диагностических ресурсов и записей, исполнение офлайн-сценариев без Windows, Wine, адаптера и автомобиля. Интерфейс приложения — на русском; подробная документация преимущественно на английском.

**Это ранняя реализация, а не полная замена Toyota Techstream. Физическая связь с автомобилем имеет статус `PHYSICAL_UNCONFIRMED`.**

## Запуск

Для консольных инструментов достаточно Python 3.11+; сторонние Python-пакеты и оригинальные базы не нужны:

```sh
git clone https://github.com/gon7187/techstream.git
cd techstream
python -m scripts.session_cli replay examples/diagnostic-session.json --output /tmp/session.json
python -m unittest discover -s tests -v
```

Для окна приложения установите системные зависимости по [инструкции](docs/getting-started.md), затем:

```sh
./techstream --demo
```

Демо создаёт собственные синтетические ресурсы. Названия, коды и значения в них — примеры, а не показания автомобиля и не рекомендации по ремонту. Launcher запускает приложение в отдельном сетевом пространстве Linux; системный firewall не меняется.

## Состояние

| Возможность | Реализовано | Граница |
| --- | --- | --- |
| Рабочая область | Поиск групп/параметров, регионы, избранное, CSV, SHA-256 | Справочные данные, без живых показаний |
| Автомобиль и ресурсы | Модель/год/опции, связанные системы, выбор кадров команд, исключения и support bits; CT/DDB и числовые преобразования | Выбор по ресурсам; реальные данные автомобиля ещё не подтверждены |
| Офлайн-диагностика | Строгий replay, OBD support/мониторы/составные значения, движки команд Toyota, lifecycle активных тестов, графики и JSON | Покрытие нативных семейств описано отдельно; синтетика не доказывает совместимость с ЭБУ |
| Записи | Воспроизведение DM, сохранённые коэффициенты сигналов, индекс и DataList TSE, команды DRS, копирование без потери неизвестных записей | Другие семейства записей отслеживаются отдельно |
| Транспорт | Framing Mongoose, identity/version JLR, raw CAN, host ISO-TP, firmware ISO и K-line | Проверены синтетические пакеты и отказы; физика не подтверждена |
| Скрипты | CSDF с нативными библиотечными функциями; XML actions/dialogs/COMM и utility bindings | Нужны выбранные дескрипторы и явно переданные провайдеры обмена |
| Калибровки и рекордер | CUW/S-record, восстановленные фрагменты передачи, симуляция программирования, нативное хранилище VIM и DRS | Полная реализация специфичных семейств программирования и рекордера ещё восстанавливается |

Подробности: [офлайн-сценарии и файлы](docs/offline-tools.md), [матрица функций](docs/full-port.md), [архитектура](docs/architecture.md), [офлайн-сеанс](docs/offline-diagnostics.md), [план проверки оборудования](docs/hardware-validation.md). Название адаптера и USB ID сами по себе не доказывают совместимость с Toyota.

В текущем native source inventory **171 контракт: 6 реализованы, 165 открыты**. Отдельно: шесть выбранных контрактов баз данных покрывают 32 точных export-цели. В матрице из 49 офлайн-функций — 39 открытых, 6 реализованных и 4 требующих физической проверки строки. Это разные масштабы учёта, не проценты готовности; подробности — в [матрице полного порта](docs/full-port.md) и [передаче разработки](docs/development-handoff.md).

## Что опубликовано

Только собственный код, документация и синтетические примеры. Оригинальные комплекты Toyota/Lexus, руководства, установщики, драйверы, ключи, активаторы и извлечённые базы в репозиторий не входят. Нужные данные следует получать отдельно с необходимыми правами: [локальный импорт](docs/getting-started.md#local-resource-import).

Для разработки и отправки изменений: [CONTRIBUTING.md](CONTRIBUTING.md). Перед публикацией логов и аппаратных трасс: [SECURITY.md](SECURITY.md).
